# AGENTS.md

Guide for AI agents working on AiberTyper. Read it before changing code.

## What this is

AiberTyper is a macOS menu bar app for typing practice. The user presses a global shortcut (default ⌥⇧T), types quotes from a collection, and sees live words per minute (WPM) and accuracy. It replaces the Raycast typer the owner used before. A Windows tray app with the same look and behavior lives in `src/windows/` (see "Windows port"). Future distribution through the gentle-shell installer is possible, but not decided.

- Language: Swift 5.10 (SwiftPM), SwiftUI + AppKit, macOS 14+.
- No dependencies. No Dock icon (`LSUIElement`).
- Windows: Go 1.24, Win32 + GDI+ through syscalls, no cgo, no dependencies, Windows 10/11 x64.
- The UI copy is in Spanish. Code, comments, identifiers and commit messages are in English.

## Commands

- `src/mac/test.sh`: compiles `Typing`, `Round`, `Session`, `HotKey`, `Keys`, `Texts*` and `src/mac/Tests/main.swift` with `swiftc` and runs the self-check. Must print `self-check OK`.
- `src/mac/build.sh`: `swift build -c release` and assembles `build/AiberTyper.app` (ad-hoc signed). Optional env: `VERSION`, `UNIVERSAL=1` (arm64 + x86_64), `SIGN_IDENTITY` (Developer ID, hardened runtime).
- `install/cask.sh <version> <sha256> [notarized 0|1, default 0]`: prints the Homebrew cask; `install/test-cask.sh` checks it (run in CI). Unnotarized casks strip the quarantine flag in `postflight_steps`.
- `install/install.sh`: one-line installer (`curl -fsSL https://raw.githubusercontent.com/AitorBermeRuiz/AitorTyper/main/install/install.sh | bash`); downloads the latest release zip into `/Applications` and opens it. curl sets no quarantine flag, so unnotarized builds open too.
- CI: `.github/workflows/ci.yml` (PRs and `main`: self-check, universal build, `install/test-cask.sh`). `.github/workflows/release.yml` (tags `v*`: build, optional sign and notarize, GitHub release, tap update). Secrets are listed in `README.md`.
- `design/mockups.sh`: renders the mockups.
- `src/mac/readme-assets.sh`: renders `docs/assets` from the real `TyperView` with a temporary history and settings (about two minutes; each demo round is typed in real time). `src/mac/readme-assets.sh banners` renders the banners only. Re-run it when the UI changes.
- `src/mac/bench.sh`: builds the app and benchmarks it end to end (about a minute, no permissions needed); fails when it is over budget. Run it **only** when a change could affect performance: the typing view, rendering, timers or `TimelineView`, the key monitor or text input, history or collection loading, anything kept in memory. Do not run it after every change (docs, texts, tests, scripts). Quote the table before and after the change. CI runs it in the `bench` job.
  - `src/mac/bench/main.swift` launches the app binary with `--bench` (temporary history and `aiber-bench` defaults, deleted on exit; the harness fails if the user's `history.json` changes or the temporary folder survives), drives it through stdin (`show`, `type <wpm>`, `hide`; `runBench` in `main.swift`) and prints CPU (`proc_pid_rusage`), RAM (phys footprint), wakeups, energy and GPU time (IOKit) per phase.
  - Budgets (top of the output code): idle CPU ≤ 1 %, idle wakeups ≤ 5/s, typing CPU ≤ 20 %, RAM peak ≤ 50 MB. Raise one only with the user's approval.
  - The app draws through WindowServer, so its own GPU time is usually 0; the WindowServer column covers the whole screen. Do not touch the panel during a run: a round under 100 % accuracy fails it. `xctrace` crashes on this Mac (macOS 26.6.2); profile with `sample <pid> 20 1`.
- `src/windows/build.sh`: cross-compiles `build/windows/AiberTyper.exe` from this Mac (Go only). `src/windows/test.sh` runs the Go tests here; from `src/windows`, `GOOS=windows go vet ./typer ./bench` and `GOOS=windows go build ./app` check the Windows-only code.
- `src/mac/export-shared.sh`: regenerates `src/windows/shared/`. Run it after any change to `Texts*.swift`, `Typing.swift` or `Round.swift`, and commit the result.
- `swift test` does not work here. Command Line Tools lack the swift-testing macro plugin. Do not add XCTest or `@Test` without checking that first.

`src/mac/test.sh` lists its sources explicitly. A new logic file (no UI or AppKit dependency that breaks `swiftc`) must be added there, or its tests will not compile.

## Running the app after a change (read this)

`swift build` does **not** update the app the user runs. The running app is `build/AiberTyper.app`. After any source change:

1. `src/mac/test.sh` and `src/mac/build.sh`.
2. Quit the running instance: `pkill -f AiberTyper.app/Contents/MacOS/AiberTyper`.
3. `open build/AiberTyper.app`.
4. Check that one process runs and that its binary is the new one (`ps -o pid,lstart,command -p <pid>` against `ls -l build/AiberTyper.app/Contents/MacOS/AiberTyper`).

Say in the report that the app was restarted and with which build. The user has asked "¿has reiniciado la app?" several times when it was still running the old binary. Never claim a UI change works until it runs in the rebuilt app.

## Architecture notes

- **Keys**: `AppDelegate` installs a local `keyDown` monitor that only handles events from the panel and performs what `PanelKey(event:picking:)` (`Keys.swift`) returns. That mapping holds every key rule: Escape, Tab, ⇧Tab and Return; arrows, Home/End and PageUp/PageDown swallowed so they never reach the hidden field; and, while the picker is open, every key goes to the picker. Change key behavior there and test it with `keyEvent()` in `src/mac/Tests/main.swift`.
- **Text input**: a hidden `TextField` (1×1, opacity 0.01) receives the keystrokes so accents and ñ compose like a normal field. The text is `session.round.typed`; every change goes through `session.type`, which saves the finished round.
- **Focus rule**: every click handler goes through `act()` in `TyperView`, which hands focus back to the hidden field. A button that skips `act()` breaks typing until the panel reopens.
- **Picker**: state lives in `Session` (`picking`, `filter`, `selection`, `matches`). `matches` is the filtered list with favorites first. Filtering uses `localizedStandardContains` (case and accent insensitive).
- **Live stats**: `TimelineView` ticks twice a second only while the panel is visible and a round has started. Keep that cost; do not add timers.
- **Manual wrap**: text is wrapped by hand, using the monospaced advance of the Iosevka font (fallback: system monospaced). `G.charsPerLine` is computed once. A proportional font would need real text layout measurement.
- **Score**: WPM counts correct characters only. Accuracy counts every keystroke, including corrected mistakes. The code is `Round.live`; test typing rules on a bare `Round`, without a `Session`.
- **Round length**: quotes are picked to fill 30–60 s at the user's recent WPM (`History.recentWPM`, default 40), capped at 90 s.

## Windows port

The Swift code is the reference; `src/windows/` follows it. For every change, keep the two apps alike:

- **Logic** (typing rules, scoring, collections, picker, history): change Swift first, run `src/mac/export-shared.sh`, then mirror the change in the `src/windows/typer` file of the same name until `go test ./...` passes. CI `check` fails when `src/windows/shared` is stale or the Go port disagrees with the vectors; add a vector to `scripts/shared/main.swift` for new behavior.
- **UI**: mirror a `TyperView` change in `src/windows/app/view.go` with the same sizes, spacing and Spanish copy. The footer hints exist in both.
- **Keys and shortcuts**: `typer/keys.go` and `typer/hotkey.go`, with Windows virtual-key codes. Windows refuses Ctrl+letter, Alt plus a typing key and Ctrl+Alt plus a typing key (AltGr); `README.md` documents both rule sets.
- **Verification**: there is no Windows machine here. The CI `windows` job runs the Go tests, the installer, and `src/windows/bench` on a real desktop: the real shortcut, Shift+Tab and Esc through `SendInput`, a typed round, a click and a drag on the panel, the shortcut recorder, an import through the file dialog, CPU and memory against the Mac budgets, and screenshots (artifact `windows-screenshots`, 1x and @2x). Download them with `gh run download` and compare with `docs/assets`. Say in the report that the Windows UI was checked through CI screenshots.
- **Constraints**: x64 only. GDI+ takes floats by value, and Go's Windows arm64 syscalls do not load float registers (Windows on ARM runs the x64 build emulated). GDI+ has no font fallback, so ★ ✓ ▾ are drawn with Segoe UI Symbol. `cmd/rsrc` writes the manifest: Common Controls 6 for task dialogs, GDI+ 1.1 for the blur, per-monitor DPI, `asInvoker` (installs and runs without administrator rights).
- **Data**: `%APPDATA%\AiberTyper\` holds `history.json` (same format as the Mac, whole-second ISO 8601 dates), `Colecciones\` and `settings.json` (the `UserDefaults` keys; `hotKey` stores a virtual key and `MOD_*` flags). There is no legacy-name migration on Windows.

## Persistence (do not break these)

- `UserDefaults`: `lang`, `pack` (collection id), `favorites`, `hotKey` (JSON; a saved shortcut the recorder would refuse falls back to ⌥⇧T), `hideImportHelp`. `Session` reads and writes its three keys through the store it is given (`.standard` in the app); each test passes a suite of its own (`freshDefaults()`), so test sessions never share settings.
- Migration from the old name (AitorTyper): at launch `migrateDefaults` copies those keys from the `com.aitor.AitorTyper` domain when the new one lacks them; `History` merges `AitorTyper/history.json` rounds it does not have; `Collection.load` copies `AitorTyper/Colecciones` only while `AiberTyper/Colecciones` does not exist, so files deleted later stay deleted. The old files are never deleted (the cask `zap` removes both).
- `~/Library/Application Support/AiberTyper/history.json`: finished rounds. Only a missing file means empty history. Any other read or decode error, at launch or when `add()` re-reads the file later, makes the history read-only: rounds are not saved, the file is kept as is and a note is shown. `add()` re-reads the file before appending, so two instances do not erase each other's rounds.
- `~/Library/Application Support/AiberTyper/Colecciones/*.json`: user collections. The format and what is skipped or refused are documented once, in `README.md` ("Your own collections"); the code is `Collection.parse`, `Collection.load` and `Collection.install` (import).
- Collection ids: built-in `general`, `stoic`, `programming`, `art-of-war`, `cinema` and `books`; files are `file:<name>.json`. A selected collection whose file disappears or fails to load falls back to `general` in memory only; the saved `pack` is kept, so it comes back when the file loads again.

## Rules for changes

- **Hotkeys**: a shortcut must leave normal typing alone in every app. The accepted and refused combinations are documented once, in `README.md` ("Shortcuts"); the code is `HotKey(event:)`.
- **Picker keys**: every plain letter goes to the filter; plain j/k never move. ⌃j/⌃k and the arrows move. The code is `PanelKey`.
- **View state**: use `@StateObject` with an `ObservableObject` for view-local state, like `HoverState`. The `@State` macro does not compile with Command Line Tools (CI with Xcode does compile it), so `src/mac/test.sh` fails when `src/mac/Sources/` uses it.
- **Built-in collections (standard)**:
  - File: one `src/mac/Sources/AiberTyper/Texts+<Name>.swift` per collection (`extension Texts`), registered as a `static let` on `Collection` and appended to `Collection.builtIn` in `src/mac/Sources/AiberTyper/Typing.swift`. `test.sh` compiles `Texts*.swift` automatically.
  - Size & uniqueness: at least **30 distinct quotes in Spanish (`es`) and 30 in English (`en`)**, paired 1-to-1 with the same count in both languages (`c.es.count == c.en.count` and `Set(texts).count == quotes.count`).
  - Length & duration: each quote must be **25–300 characters** (`Collection.maxChars`, 90 s at 40 wpm), single-spaced, with no newlines or wide/emoji characters (`Collection.parse` must accept all quotes with `skipped == 0`), and include enough quotes ≤150 chars so `pickQuotes` always forms rounds of **30–90 s** (even at 20 wpm).
  - References: every quote in a themed collection (`id != "general"`) must have a non-empty, verifiable `source` (e.g. `"Author, Work"` or `"Author, Work, section"`). Do not add unattributed, paraphrased or misattributed quotes.
  - Self-check: `src/mac/test.sh` enforces all of the above automatically over every entry in `Collection.builtIn`.
- **Themes**: the owner plans to switch between several styles later. The current style is the Aiber Bermejo palette (`design/brand/README.md`): background `#1B1113`, text `#F6EEF0`, pink `#F497A9`, neon `#E83A59`, muted `#AA989C`, border `#3C262B`, yellow `#F5D547` for NEW tags. Do not use the Kanagawa/gold palette; the owner rejected it. Other mockups are in `design/mockups/`.
- **Window**: `safeAreaRegions = []` on the hosting controller is required. Without it, resizing the transparent titlebar panel crashes AppKit (constraint loop). Do not remove it.
- **Import**: validate every file before copying it into the folder (`Collection.install`; `AppDelegate` only shows the dialogs). Show the format help once, with "No volver a mostrar este mensaje nunca más".
- **Strings**: UI copy in Spanish, with the same register as existing strings (voseo is not used in UI).
- **Docs**: when a shortcut, option or message changes, update `README.md` and `README.es.md` (kept in sync with each other) and the footer hints in `TyperView` (kept matching the real keys); re-render `docs/assets` when the UI changes.

## Testing and verification

- New logic: write the assert in `src/mac/Tests/main.swift` first, see it fail, then implement. Test through public functions, never internal storage.
- UI behavior (clicks, focus, key handling, layout) is not covered by the self-check. Verify it in the rebuilt app and say clearly what was and was not checked.
- Known untested areas: mouse interaction of the picker and buttons, hover highlight and pointing-hand cursor reset (when a button disappears or the panel loses key), and very long collection lists (the picker has no scroll).

## Git

- Remote: public `github.com/AitorBermeRuiz/AitorTyper`, default branch `main`. Work goes through branches and pull requests.
- `main` ruleset: PR required, linear history, required check `check` (the `ci.yml` job). Merge with squash or rebase; update a PR branch by rebasing, never with GitHub's "Update branch" merge.
- Homebrew tap: `github.com/AitorBermeRuiz/homebrew-tap`, `Casks/aibertyper.rb` is written by the release workflow from `install/cask.sh`. To fix a published cask, change `install/cask.sh` and release a patch tag; the workflow rewrites the cask.
- License: MIT (`LICENSE`). Vendored skills in `.agents/skills/` keep their upstream MIT `LICENSE` files.
- Commit style: Conventional Commits (`feat:`, `fix:`, `perf:`, `chore:`, `feat(texts):`).
- Do not commit, push or create branches unless the user asks. When the user does ask for commits, split them by phase (see the history: one commit per feature, tests with the code).
- Do not commit `build/` or `.build/` (both ignored). Do not commit scratch files.
